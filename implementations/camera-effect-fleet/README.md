# camera-effect-fleet — Xiaomi camera render-effect asset containers

A clean-room structural probe for the opaque `.bin` files under
`proprietary/vendor/etc/camera/resources/render/Effect/`. These are **artistic
assets**, not firmware: retouch masks and colour textures consumed by the
vendor camera render pipeline. What is reverse-engineered here is the
**container grammar**, never the artwork.

## The result in one sentence

Every one of the 35 `.bin` files in the `Effect/` tree of
`TheMuppets/proprietary_vendor_xiaomi_diting` @ `lineage-22.2` is a bare
**28-byte header followed by exactly `width × height × 4` bytes of pixel data**,
with **zero slack** and an identical constant header tail. No length field, no
magic string, no compression, no trailer.

## Header grammar — measured, 35/35

| offset | type | value | meaning |
|---|---|---|---|
| `0x00` | u32 LE | varies | width |
| `0x04` | u32 LE | varies | height |
| `0x08` | u32 LE | **4** in 35/35 | bytes per pixel |
| `0x0c` | u32 LE | **1** in 35/35 | plane count |
| `0x10` | u32 LE | **0** in 35/35 | reserved (zero) |
| `0x14` | u32 LE | **99 (`0x63`)** in 35/35 | format constant / version |
| `0x18` | u32 LE | **0** in 35/35 | reserved (zero) |

Invariant: `filesize == 28 + width × height × 4`. Verified on all 35 files,
sizes from 4,124 B to 6,000,028 B.

Four bytes per pixel plus a constant fourth channel on most masks suggests
BGRA, but **the channel order is not established** and is marked `[OPEN]`.
The pixel payload classes are measured from channel-identity statistics, not
assumed from filenames.

Written 2026-11-20 from public directory listings and direct byte measurements
only. No proprietary code, headers, documentation or artwork is committed. The

## Usage

```bash
cd implementations/camera-effect-fleet
python3 -I make_fixture.py
python3 -m unittest discover -q
python3 -I effect_probe.py <file>.bin --brief
python3 -I effect_probe.py <file>.bin        # full JSON
```
