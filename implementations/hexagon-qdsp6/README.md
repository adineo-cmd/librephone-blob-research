# hexagon-qdsp6 — clean-room structural probe for Hexagon firmware containers

A stdlib-only parser for the container family that carries Qualcomm Hexagon modem and
ADSP images: monolithic `qdsp6sw.mbn`, split `*.mdt` + `*.bNN`, and the self-contained
single-file form.

It does **not** decompress CLADE, decode Hexagon instructions, or verify signatures. It
answers one question honestly: *what is the container's structure, and does it obey its
own invariants?*

## What it establishes

| property | how |
|---|---|
| ELF header and all program headers | `Elf32_Ehdr` / `Elf32_Phdr`, little-endian |
| Hexagon arch version | `e_flags` bits[11:0] → `v60`…`v79` via LLVM's `EF_HEXAGON_ISA_*` table; unnamed values reported as `unknown(0x..)` |
| container generation | `monolithic` / `split-mdt` / `self-contained` |
| the metadata (hash) segment | located by `p_flags` **type field** `== 0x2`, as `mdt_loader.c` does |
| relocatable images | `BIT(27)` = `QCOM_MDT_RELOCATABLE` |
| file-space gaps and overlaps | exact byte accounting against the file size |
| zlib segments | inflate and report the ratio, with `eof`/slack checks |
| embedded ELF magics | reported, not assumed to be headers |

## The invariant that identifies the generation

A **header-only** image (`split-mdt`) has program header 0 as
`p_type=PT_NULL, p_offset=0, p_memsz=0, p_filesz=ehsize+phnum*phentsize, p_flags=0x07000000`
— segment 0 *is* the ELF header plus the program-header table. Monolithic images instead
open with a real `PT_LOAD` at file offset 0. Verified on the 39 `EM_QDSP6` objects in this
corpus, which parse with zero invariant violations.

For split images the sibling rule is: `.b00` equals the header table, and `.bNN` exists for
every program header with `p_filesz > 0`, and is absent exactly when `p_filesz == 0`.

## Flags, named correctly

The vendor's `p_flags` bits are the ones mainline Linux names, from
`include/linux/soc/qcom/mdt_loader.h` (public since v4.11):

```c
#define QCOM_MDT_TYPE_MASK   (7 << 24)   /* bits[26:24] */
#define QCOM_MDT_TYPE_HASH   (2 << 24)   /* this is the hash/metadata segment */
#define QCOM_MDT_RELOCATABLE BIT(27)     /* 0x08000000 */
```

The low three bits remain standard `PF_R`/`PF_W`/`PF_X`. **The kernel finds the metadata
segment by the type field, not by `p_type`** — which is why a metadata segment can be
`PT_NULL` and still be the one that gets hashed. This parser reports the same segment the
kernel would.

## Usage

```
python3 -I hexagon_probe.py <file> [--json out.json] [--brief] [--quiet]
python3 -I hexagon_probe.py --dir <dir> [--json out.json]
```

Exit codes: `0` valid, `1` parseable but violating an invariant, `2` unparseable.

## Tests

```
python3 -I make_fixture.py
python3 -m unittest -q
```

47 tests, 1 skip. Run the suite **without** `-I`: that flag drops the CWD from `sys.path`,
so the module import fails. The CLI itself is meant to run **with** `-I`.

Fixtures are synthetic and regenerated by `make_fixture.py`. `fixtures/.gitignore`
excludes the whole directory — the repo root `.gitignore` covers `*.mbn`/`*.mdt`/`*.bNN`
but not the `.hexbin` extension used here, so the exclusion is made local.

## Clean-room statement

Written from public sources only: the ELF gABI and `include/uapi/linux/elf.h`;
`drivers/soc/qcom/mdt_loader.c` and `include/linux/soc/qcom/mdt_loader.h` (GPL-2.0-only,
torvalds/linux); `drivers/remoteproc/qcom_q6v5_pas.c` (GPL-2.0-only); and
`llvm/include/llvm/BinaryFormat/ELF.h` (Apache-2.0 WITH LLVM-exception) for `EM_QDSP6` and
the `e_flags` architecture table. Plus own structural measurements of the payload bytes.

No decompiled code, no proprietary documentation and no vendor header was read. Every
number printed is either read from the file in front of the parser, or one of the public
constants named above. Anything else is reported as `[OPEN]` rather than guessed.

## Known limits

- No CLADE/Q6ZIP decompression. Only zlib is inflated, because only zlib is publicly
  specified.
- No instruction decoding. `p_flags` `PF_X` and packet structure are not proof of code;
  see the heuristic discussion in `research/fleet/qdsp6sw-container.md` §5.2.
- No signature verification. The SHA-384 table can be recomputed, but nothing here checks
  the certificate chain.
- The metadata *header* fields beyond the sizes used for the layout chain are not
  interpreted.
